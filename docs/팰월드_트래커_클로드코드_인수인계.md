# Claude Code 인수인계 — 팰월드 4거점 트래커

> **v3 요약**
> - **새 레포를 만들지 않는다.** 지금 이 `checklist` 레포에 `/pal` 라우트를 추가한다.
> - **`ADMIN_TOKEN` 폐기.** 인증은 기존 **`CONTROL_KEY`** 하나로 통일한다.
> - **오버레이를 새로 만들지 않는다.** 계산 결과를 기존 `lists`/`items` 에 sync 하면
>   기존 `/o/[id]` 가 `/o/pal` 로 그대로 띄워준다.
> - **DB 테이블은 전부 `pal_` 접두사.** 기존 `public.items` 와 이름이 충돌한다.
> - 체크리스트는 건설이 아니라 **재료 파밍**에서 시작한다.

## 0. 시작 전 준비

새로 만들 것은 없다. 이미 다음이 준비돼 있다:

```
docs/팰월드_1.0_4거점_설계도.md            ← 게임 데이터 원본
docs/팰월드_트래커_기획서.md               ← 스키마·엔진·화면 (v3)
docs/팰월드_트래커_클로드코드_인수인계.md  ← 이 파일
```

`.env.local` 도 그대로 쓴다. **추가할 환경변수 없음:**

```
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY
SUPABASE_DB_URL
CONTROL_KEY          ← 체크리스트와 팰월드가 같이 쓴다
```

## 1. 두 프로젝트가 합쳐지는 지점

```
[팰월드 트래커 /pal]                        [기존 체크리스트]
 재고 입력 ─→ BOM 계산 ─→ 할 일 N개 ──sync──→ lists(id='pal') + items
                                                       │
                                                       ↓ (기존 Realtime)
                                               /o/pal  오버레이
```

`lists.id` 가 `text primary key` 라서 `'pal'` 이라는 고정 id 를 쓸 수 있다. 그러면
오버레이 URL 이 `/o/pal` 이 되는데 **이건 새 라우트가 아니라 기존 `/o/[id]` 가 처리하는
URL** 이다. `scale` · `hideDone` 같은 기존 쿼리 옵션도 그대로 먹는다.

**그래서 안 만든다: `pal_overlay_state`, `/o/pal` 전용 페이지, 오버레이 payload 설계,
Realtime 구독 배선, OBS 재설정.**

## 2. CLAUDE.md 초안 (repo 루트에 저장)

```markdown
# 치지직 오버레이 도구 모음

## 무엇
한 사이트 안에 방송용 도구가 라우트로 나뉘어 들어 있다.

| 라우트 | 공개 | 내용 |
|---|---|---|
| /control        | 🔒 | 체크리스트 컨트롤 (팰월드 목록도 읽기 전용으로 표시) |
| /o/[id]         | 🌐 | 오버레이 — 체크리스트도 팰월드(/o/pal)도 전부 여기 |
| /api/mutate     | 🔒 | 체크리스트 쓰기 |
| /pal            | 🔒 | 팰월드 4거점 트래커 (탭 UI) |
| /api/pal/mutate | 🔒 | 팰월드 쓰기 + 체크리스트 sync |

## 스택
Next.js 15 App Router + TypeScript + Supabase + Vercel

## 반드시 지킬 것
- **인증 키는 CONTROL_KEY 하나뿐이다.** ADMIN_TOKEN 같은 별도 변수를 만들지 말 것.
  - 서버 컴포넌트: lib/auth.ts 의 keyMatches(searchParams.key)
  - API 라우트:   lib/auth.ts 의 requireKey(req)  (x-control-key 헤더 또는 ?key=)
  - 클라이언트:   components/Gate.tsx, localStorage 키 이름은 'control_key' 로 공유
- **쿠키·middleware.ts 를 도입하지 말 것.** /o/* 오버레이까지 걸려서 방송이 깨진다.
- **팰월드용 오버레이를 새로 만들지 말 것.** 계산 결과를 pal_sync_list() 로
  lists(id='pal') + items 에 밀어넣으면 기존 오버레이가 그대로 렌더한다.
- **sync 는 전체 삭제 후 재삽입이 아니라 diff upsert.** 삭제 이벤트가 먼저 나가면
  방송 중 오버레이가 빈 화면으로 깜빡인다.
- **service_role 키는 app/api/ 아래에서만** adminClient() 로 쓴다. 클라이언트 번들 금지.
- **팰월드 테이블은 전부 pal_ 접두사.** 접두사 없는 items/lists 는 체크리스트 것이다.
- **pal_* 테이블은 RLS enable 만 하고 정책을 만들지 않는다** = anon 전면 차단.
  방송에 공개되는 건 sync 로 내보낸 items.label 뿐이다. 재고 총량을 감추고 싶으면
  label 을 "발화 기관 32%" 형태로 내보낸다 (pal_settings 토글).
- **체크리스트는 저장물이 아니라 파생물이다.** pal_checklist 에 저장하는 건 건설
  단계의 done 플래그뿐. 파밍/제작 완료는 재고로 판정한다.
- BOM 계산은 **재고를 먼저 차감하고 하위 전개**한다.
  stock 객체는 반드시 복사본을 쓴다 (원본 변형 금지).
- 게임 수치는 전부 DB 에서 읽는다. **코드에 하드코딩 금지** — 값이 틀린 항목이 있어서
  /pal 데이터 탭에서 고칠 수 있어야 한다.
- body 에 배경색을 넣지 않는다 (OBS 투명 배경).

## 문서
- docs/팰월드_1.0_4거점_설계도.md — 게임 데이터 원본. 시드 데이터의 출처.
- docs/팰월드_트래커_기획서.md — 통합 방식, 스키마, 계산 엔진, 우선순위, 화면.

## 명령어
npm run dev / npm run build / npm run typecheck / npm run db:setup
```

## 3. 1단계 프롬프트 — 접합부 먼저 (그대로 붙여넣기)

```
docs/팰월드_트래커_기획서.md 를 읽어줘. 새 프로젝트가 아니라 지금 이 레포에
팰월드 트래커를 붙이는 작업이고, 1단계는 두 앱을 잇는 접합부다.

1) supabase/schema.sql 에 두 줄 추가 (기존 동작이 바뀌면 안 된다)
   alter table public.lists add column if not exists source text not null default 'manual';
   alter table public.items add column if not exists ref text;
   create unique index if not exists items_list_ref_idx
     on public.items (list_id, ref) where ref is not null;
   - 부분 인덱스인 이유: 손으로 만든 항목은 ref 가 null 이고 여러 개 존재한다.

2) pal_sync_list(p_items jsonb) RPC 작성 — 기획서 2-4 참고
   - lists(id='pal', source='pal') upsert
   - 목록에서 사라진 ref 만 delete
   - 나머지는 insert ... on conflict (list_id, ref) do update
   - 전부 한 트랜잭션. 전체 삭제 후 재삽입 금지 (오버레이가 깜빡인다)
   - revoke execute ... from anon, authenticated

3) lib/types.ts 의 List 타입에 source 추가, Item 타입에 ref 추가

4) /control 에서 source='pal' 목록은 읽기 전용으로:
   - "🤖 트래커가 관리" 배지 + /pal 링크
   - 항목 추가/수정/삭제/순서변경/체크박스 비활성
   - 목록 이름변경·삭제·정렬은 허용

5) app/api/mutate/route.ts 방어: rename_list / delete_list 를 제외한 action 이
   source='pal' 목록을 대상으로 오면 400 으로 거절

npm run db:setup, npm run build, npm run typecheck 가 통과하는지 확인하고,
기존 체크리스트 동작(추가·체크·삭제·오버레이 실시간 반영)이 그대로인지 확인해줘.
```

## 5. 이후 단계 프롬프트

**3단계 — 스키마 + 시드**
```
기획서 6번 스키마를 supabase/schema-pal.sql 로 작성해줘.
기존 supabase/schema.sql 은 1단계에서 추가한 두 줄 외엔 건드리지 말 것.

- 테이블 이름은 전부 pal_ 접두사. 접두사 없는 items 는 체크리스트 테이블이다.
- pal_overlay_state 는 만들지 않는다 (오버레이는 lists/items 를 쓴다).
- 기존 schema.sql 과 같이 idempotent 하게
- RLS: pal_* 전부 enable 만 하고 정책 없음 = anon 전면 차단
- scripts/setup-db.mjs 가 이 파일도 적용하도록 확장

이어서 docs/팰월드_1.0_4거점_설계도.md 를 근거로 시드 데이터를 만들어줘.
- pal_farm_sources: 16-2 의 A~E 분류를 획득처로. method(auto/manual), icon, place,
  requires_structure(물질 생성기·원유 추출기·가축 목장) 채울 것
- pal_items: 원재료 + 중간재 전부. 최하위 재료는 source_id 를 반드시 채운다
- pal_recipes: 16-1의 레시피 트리 전부. tier 는 16-3 의 1차/2차/3차/4차 그대로.
  yield 는 전부 1로 두되 컬럼은 유지
- pal_structures / pal_structure_costs: 16-4 거점 ①~④ + 공통 세트
- pal_structure_unlocks: 고대 문명 화로 → 팰키사이트/솔라이트 주괴 등 선행 관계
- pal_pals / pal_assignments: 9장 추천 팰과 거점별 배치표
- unlock_score, base weight 는 기획서 8번 표 그대로
시드도 idempotent 하게 (on conflict do update).
```

**4단계 — 계산 엔진**
```
lib/pal/engine/ 에 계산 엔진을 작성해줘. 기획서 7번 의사코드 기준.
- expand(itemId, qty, stock): 재고 선차감 후 하위 전개, 순환 참조 감지
- shortage(): 미완성 건축물 목록 → 최하위 재료별 부족량 + blockedBy 집계
- farmTasks(): 부족 재료를 획득처로 묶고 farmScore 로 정렬 (기획서 8-1)
- buildTasks(): 건설 우선순위 (기획서 8-2)
- toChecklist(): 8-3 순서로 합쳐 [{ref, label, done, position}] 배열 생성
  ref 는 'farm:hunt_fire' / 'build:ancient_furnace' 형태의 안정적인 문자열
단위 테스트 작성. 특히 아래를 반드시 검증할 것:
- 재고 선차감이 하위 전개를 실제로 줄이는지
- stock 원본이 변형되지 않는지 (복사본 사용)
- 자동 획득처인데 requires_structure 가 미완성이면 건설이 최상단으로 올라오는지
```

**5단계 — 재고 탭**
```
5: 재고 탭. 획득처별 그룹, 절대값 입력과 증분 입력(+250) 둘 다,
   낙관적 업데이트, /api/pal/mutate 로 저장 (x-control-key 헤더).
   부족량 0인 재료는 흐리게. 여기까지 되면 앱이 굴러간다.
```

**6단계 — 할 일 탭 + sync (오버레이가 살아나는 지점)**
```
6: 할 일 탭 + 체크리스트 sync.
   - 8-3 합산 목록 상위 N개 + 최근 완료 3개 → toChecklist()
   - /api/pal/mutate 에서 재고·건설체크가 바뀔 때마다 재계산 후 pal_sync_list() 호출
   - /pal 에 "오버레이 URL: /o/pal" 안내와 마지막 sync 시각 표시
   - pal_settings 에 '총량 노출' 토글 — 끄면 label 을 "발화 기관 32%" 로 내보낸다
   오버레이 렌더링 코드는 한 줄도 쓰지 않는다. 기존 /o/[id] 가 그대로 띄운다.
   실제로 /o/pal 을 열어서 실시간 반영되는지 확인할 것.
```

**7~10단계 — 나머지 탭**
```
7:  파밍 탭 (획득처별 전체 목록 + 재료별 보유/필요/부족 진행률 바)
8:  제작 탭 (tier 순 트리, 단계별 접기/펼치기, 각 항목에 필요/보유/부족)
9:  거점 탭 (①~④ 서브탭: 건축물 체크박스 + 팰 배치표, 체크 시 sync 재실행)
10: 데이터 탭 (레시피·건축물 비용·unlock_score·획득처 직접 수정)
```

**11단계 — 마무리**
```
README 에 팰월드 트래커 섹션을 추가해줘.
```

## 6. 데이터에 남은 불확실성 (시드에 주석으로 남길 것)

| 항목 | 상태 |
|---|---|
| 제작 산출량(yield) | 전부 1로 가정. 실제로 여러 개 나오는 레시피가 있으면 `/pal` 데이터 탭에서 수정 |
| 고대 문명 부엌·재배기 전력 | 미확인 (부엌은 전력 필요한 것만 확인됨) |
| 배합기 부모 팰의 거점 정원 포함 여부 | 미확인 |
| 대형 발전기 재료 | 1.0.3에서 150으로 하향, paldb는 200 표기 |
| 물질 생성기 요구 적성 | 공략 기준 채굴6/벌목6, paldb 내부값은 수작업 |
| 길드 상자 / 대형 부엌 | 재료 확인 완료 (설계도 16-4 반영) |
